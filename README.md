# Gradebook — учебный журнал

**Gradebook** — автономное веб-приложение для ведения учебного журнала: групп, подгрупп, занятий, оценок, комментариев, календаря и карточек студентов.

Текущая версия интерфейса: **14**.

**[Скачать Gradebook-v14.html](https://github.com/meshcheryakovaa/gradebook/releases/download/v14/Gradebook-v14.html)** — один файл со встроенными стилями и скриптами. Откройте его в браузере без установки и распаковки. При переходе со старого файла экспортируйте базу в JSON и импортируйте её в новую версию: браузер может хранить данные разных локальных файлов отдельно.

Приложение работает в браузере без сервера и без базы данных: основные данные сохраняются локально в браузере. При необходимости базу можно экспортировать в JSON или синхронизировать с Яндекс Диском.

## Возможности

- группы и подгруппы;
- добавление студентов по одному или списком;
- собственные типы занятий с цветом и обозначением (`Л`, `ПР`, `ЛР`, `А` и т. д.);
- обычные занятия, занятия для подгрупп и объединённые занятия нескольких групп;
- журнал с оценками по датам и редактированием прямо в таблице по двойному щелчку;
- средний балл каждого студента и статистика абсолютной и качественной успеваемости;
- списки студентов по алфавиту;
- комментарии к результатам студентов;
- карточка студента со всеми его занятиями, оценками и комментариями;
- переход к предыдущему и следующему студенту из карточки;
- рамки у оценок «2», «Н», «Н/А» и других текстовых обозначений;
- календарь занятий в режимах **месяц / неделя / список**;
- фильтрация занятий по группе и типу;
- табличный режим заполнения занятия;
- матричный режим с рассадкой студентов по аудитории;
- режим проведения занятия со звёздами/баллами;
- копирование оценок из одного занятия и вставка в другое с сопоставлением по студентам;
- печать журнала на A4;
- полноэкранный режим;
- светлая и тёмная темы;
- экспорт и импорт базы в JSON;
- синхронизация с Яндекс Диском;
- аккаунты с паролями, личные и общие журналы;
- объединение параллельных правок по полям и выбор спорных значений;
- очередь офлайн-изменений и неизменяемая история обмена на Яндекс Диске.

## Редактирование оценок в таблице журнала

Дважды щёлкните по клетке с оценкой в общей таблице журнала, и в ней появится поле ввода. Новое значение сохраняется сразу, без кнопки «Сохранить»: по клавише **Enter** (с переходом к следующему студенту ниже), **Tab** (к следующему занятию справа; **Shift+Enter** и **Shift+Tab** — в обратную сторону) или при щелчке в другом месте. **Esc** отменяет правку. Комментарий к результату при этом не меняется; если стереть оценку у результата без комментария, запись удаляется. Клетки занятий чужих подгрупп пропускаются. Средний балл и статистика пересчитываются сразу.

## Рамки оценок

В таблице журнала автоматически появляются рамки:

| Значение | Рамка |
| --- | --- |
| 2 (в том числе 2,0) | Красная сплошная |
| Н (без учёта регистра) | Жёлтая сплошная |
| Н/А (в том числе с пробелами) | Красная пунктирная |
| Другие текстовые обозначения, например «зач», «б», «незач» | Пунктирная цвета акцента |

Пустые клетки, остальные числовые оценки и записи вида «2 балла» не выделяются рамкой. Рамки совместимы с цветами типов занятий и метками комментариев, а в печати отображаются чёрным цветом.

## Средний балл и статистика

Столбец **«Средний балл»** показывает среднее арифметическое числовых оценок от 2 до 5 по занятиям выбранного типа (или всем занятиям при фильтре «Все»). Пропуск «Н» (без учёта регистра) учитывается как оценка 2. Допускаются дробные оценки с точкой или запятой. Пустые значения, «Н/А», зачёты и записи вида «5 баллов» исключаются. Занятия других подгрупп также не учитываются. Если оценок нет, отображается «—».

Под таблицей выводится текущая статистика по средним баллам:

- **Абсолютная успеваемость** — число студентов со средним баллом ≥ 3 / число студентов с числовыми оценками × 100 %.
- **Качественная успеваемость** — число студентов со средним баллом ≥ 4 / число студентов с числовыми оценками × 100 %.
- Отдельно показано количество студентов без числовых оценок; они не входят в знаменатель процентов. Если оценок нет ни у кого, проценты показываются как «—».

Пороги проверяются до округления среднего балла; в таблице он отображается с двумя знаками после запятой. Это оперативные показатели по текущим оценкам, а не расчёт по итоговым отметкам. Статистика также включается в печатную версию.

Все списки студентов сортируются по ФИО с учётом русского алфавита, независимо от старого поля `order`. Вверху карточки есть кнопки **«Предыдущий»** и **«Следующий»** и номер позиции. Из журнала переход выполняется по группе, из занятия — по его участникам (включая подгруппы и объединённые группы). На границах списка соответствующая кнопка отключена. Если есть несохранённые изменения, перед переходом запрашивается подтверждение их отмены; чтобы сохранить их, сначала нажмите **«Сохранить»**.

Проверка расчётов и сортировки (Node.js, без установки зависимостей):

```bash
node --test tests/performance.test.cjs
```

Проверка всего приложения, включая редактирование в таблице, карточку студента, импорт, облачные снимки и рамки (Node.js 24):

```bash
npm ci
npm test
```

Сборка автономного HTML-файла без сторонних зависимостей:

```bash

```

Результат: `dist/Gradebook-v14.html`.

## Выпуск новой версии

Релизы публикуются автоматически через GitHub Actions (`.github/workflows/release.yml`) при добавлении/изменении `release-notes/v*.md` в `main`, отправке тега или ручном запуске. Для публикации из `main` номер берётся из `index.html`. Для выпуска версии, например 14.1, обновите номер версии в `index.html`, `README.md` и `scripts/build_standalone.py`, добавьте описание в `release-notes/v14.1.md` (первая строка вида `# Краткое название` станет подзаголовком релиза), закоммитьте изменения в `main` и отправьте тег:

```bash
git tag v14.1
git push origin v14.1
```

Workflow запустит тесты, соберёт `Gradebook-v14.1.html`, проверит встроенный JavaScript и опубликует релиз с этим файлом. Его также можно запустить вручную во вкладке **Actions → Release Gradebook → Run workflow**, указав номер версии.

## Быстрый запуск

### Вариант 1 — открыть как обычный HTML-файл

Клонируйте репозиторий:

```powershell
git clone https://github.com/meshcheryakovaa/gradebook.git
cd gradebook
```

После этого откройте файл:

```text
index.html
```

например двойным щелчком в Проводнике Windows.

### Вариант 2 — локальный HTTP-сервер

Этот вариант рекомендуется для максимально предсказуемой работы браузерных API.

Если установлен Python:

```powershell
cd gradebook
python -m http.server 8000
```

Откройте в браузере:

```text
http://localhost:8000/
```

Для остановки сервера нажмите `Ctrl+C` в терминале.

## Первичная настройка

### 1. Создайте учебную группу

Откройте:

**Настройки → Группы**

Введите название группы, например:

```text
НДб-25-1/ВИШ
```

При необходимости внутри группы создайте подгруппы.

### 2. Добавьте студентов

Откройте:

**Настройки → Студенты**

Можно:

- добавить одного студента;
- вставить список студентов сразу;
- назначить студенту подгруппу;
- изменить или удалить студента.

При массовом добавлении вводите по одному ФИО на строку.

### 3. Укажите дисциплину и учебный год

На главной странице заполните поля:

- **Дисциплина**;
- **Учебный год**.

Например:

```text
Физика
2026/2027
```

Эти данные также можно изменить через **Настройки → Общие**.

### 4. Настройте типы занятий

Откройте:

**Настройки → Типы занятий**

По умолчанию есть:

- Лекция — `Л`;
- Практическое занятие — `ПР`;
- Лабораторная работа — `ЛР`.

Для каждого типа можно задать своё название, сокращение и цвет.

## Создание занятия

На главной странице нажмите:

**+ Занятие**

Укажите:

- дату;
- количество часов;
- одну или несколько групп;
- при необходимости конкретные подгруппы;
- тему;
- вид занятия.

После создания занятие сразу можно открыть и заполнить.

### Объединённые занятия

Одно занятие может относиться сразу к нескольким группам или подгруппам.

Такое занятие отображается в журналах всех выбранных групп, но является одной общей записью. Внутри занятия студенты групп показываются отдельными блоками.

## Выставление оценок

Откройте занятие нажатием на дату в журнале.

В табличном режиме для каждого студента доступны:

- поле **Результат**;
- поле **Комментарий**.

В поле результата можно использовать не только числовые оценки, но и текстовые обозначения, например:

```text
5
4
зач
н
б
```

После редактирования нажмите **Сохранить**.

Если есть несохранённые изменения, приложение показывает соответствующий индикатор и предупреждает перед выходом.

## Карточка студента

Нажмите на ФИО студента в журнале или внутри занятия.

Откроется карточка со всеми занятиями этого студента. В ней можно сразу изменять:

- оценки;
- комментарии.

После редактирования нажмите **Сохранить**.

## Календарь занятий

На главной странице переключитесь с вкладки **Журнал** на **Календарь занятий**.

Доступны три режима:

- **Месяц**;
- **Неделя**;
- **Список**.

Можно фильтровать календарь по группе и типу занятия.

Нажатие на карточку занятия открывает его журнал. Кнопка `+` на нужной дате позволяет сразу создать занятие на этот день.

## Рассадка студентов

Внутри занятия переключитесь:

**Таблица → Матрица**

В режиме **Расстановка** можно:

1. указать количество строк и столбцов;
2. нажать на нужное место;
3. назначить на него студента.

Рассадка сохраняется в базе журнала.

### Проведение занятия

В матричном представлении выберите режим:

**Проведение занятия**

Нажимая на студента, можно добавлять или убирать звёзды. Накопленное число может быть перенесено в результат занятия как количество баллов.

## Копирование оценок между занятиями

В открытом занятии доступны кнопки:

- **Скопировать оценки**;
- **Вставить из буфера**.

Оценки сопоставляются по внутреннему идентификатору студента, поэтому порядок студентов в таблице не важен.

Перед вставкой приложение показывает подтверждение и сообщает, сколько оценок будет вставлено или заменено. Комментарии при вставке оценок не удаляются.

## Комментарии в общем журнале

Откройте:

**Настройки → Общие**

и включите:

**Просмотр комментариев в общей таблице**.

После этого ячейки с комментариями получают индикатор. Нажатие на результат студента показывает комментарий во всплывающем окне.

## Резервное копирование

Основная база хранится в `localStorage` браузера.

Это означает, что данные привязаны к конкретному браузеру и его профилю. Очистка данных сайта или профиля браузера может удалить локальный журнал.

Поэтому рекомендуется регулярно использовать:

**Настройки → Экспорт базы**

Будет сохранён файл вида:

```text
journal_backup_2026-10-23.json
```

Для восстановления используйте:

**Настройки → Импорт базы**

> Обычный JSON заменяет текущую базу: в общем журнале эти замены и удаления затем получат остальные участники. Экспорт v14 содержит историю операций. При импорте такой копии в тот же журнал история объединяется, сохраняя конфликты и ещё не отправленные изменения. Для другого журнала импортируется только видимая база.

## Аккаунты и синхронизация v14

### Быстрый запуск для двух преподавателей

1. Каждый скачивает **Gradebook-v14.html** и открывает его в современном браузере. При ограничениях браузера используйте `http://localhost:8000/` по инструкции выше.
2. На каждом устройстве откройте **Настройки → Яндекс Диск → Ручной OAuth-токен** и сохраните **один и тот же токен**. Это токен одного OAuth-приложения с правом `cloud_api:disk.app_folder`. Client Secret не нужен; токен не входит в экспорт и облачные пакеты.
3. Нажмите **Аккаунты** в шапке. Каждый задаёт собственные логин, пароль (не менее 8 символов), имя и нажимает **Создать аккаунт**.
4. Для совместной работы оба выбирают **Общий: совместная работа** и одинаковое имя журнала, например `основной`. Для независимых данных выберите **Личный: отдельная база**. При личном режиме каждый аккаунт получает отдельное пространство.
5. Первый преподаватель создаёт/импортирует журнал и нажимает **Синхронизировать сейчас**. Второй синхронизируется и получает этот журнал.
6. Можно редактировать свои локальные копии без интернета. При последующем обмене изменения объединяются. Если один человек изменил оценку, а другой комментарий к ней, сохраняются обе правки.

Войти на другом устройстве можно через **Аккаунты → Войти / открыть журнал** с тем же логином и паролем. Для ранее использованного аккаунта есть явный **Вход офлайн**. Сессия запоминается в текущей вкладке; **Выйти** возвращает прежнюю базу без аккаунта. Чтобы переключить журнал, снова войдите, выбрав нужный режим/название.

### Переход с v13

1. В прежнем файле экспортируйте базу в JSON.
2. В v14 подключите Диск, создайте аккаунт и откройте общий или личный журнал.
3. Импортируйте старый JSON **один раз на одном устройстве**, затем синхронизируйте. Остальные участники получают данные через синхронизацию, не импортируя свои устаревшие копии поверх общей базы.
4. После проверки экспортируйте резервную копию уже из v14.

Версия 14 не записывает `app:/journal-sync.json` и `app:/journal-versions`: старые файлы остаются для v13. Эти версии не обмениваются изменениями между собой. База без аккаунта доступна локально; для облачного обмена v14 требуется вход в аккаунт.

### Правила объединения

| Ситуация | Результат |
| --- | --- |
| Разные студенты, занятия или поля | Правки объединяются автоматически |
| Одинаковое значение введено одновременно | Одно значение без лишнего спора |
| Разные оценки в одной клетке | Оба варианта сохранены; появляется кнопка «Спорные изменения» |
| Удаление одновременно с редактированием | Удаление/сохранение предлагается выбрать явно |
| Оборвалась связь после отправки | Пакет остаётся в очереди; повтор проверяет файл без перезаписи |
| Запись появляется на Диске после завершения обмена | Она придёт при следующем обмене |

Пока спор не решён, журнал показывает детерминированный временный вариант. Нажмите уведомление либо **Аккаунты → Спорные изменения**, выберите значение и синхронизируйте. История сохраняет исходные варианты. Одновременные разные решения тоже образуют новый спор. Массивы (например, список подгрупп или рассадка) объединяются как одно поле с выбором целого варианта.

Кнопки **Синхронизировать**, **Отправить** и **Загрузить** выполняют одинаковый двусторонний обмен. Кнопки принудительной перезаписи всей облачной базы больше нет. **История версий** показывает историю пакетов; для восстановления используйте экспорт/импорт JSON.

**Автосинхронизация** отправляет сохранённые правки с задержкой 2,2 секунды, проверяет входящие изменения раз в минуту и при восстановлении сети. Пока есть несохранённая форма, обмен откладывается. Под шапкой видно состояние отправки и ошибки; при сохранении прямо во время обмена может потребоваться повтор. Работа локально сохраняется до обращения к сети.

### Что хранится на Диске

- `app:/gradebook-v14/accounts/<hash-логина>.json` — логин, имя и проверочное значение PBKDF2-SHA256 с солью (310 000 итераций); пароль открытым текстом не хранится.
- `app:/gradebook-v14/workspaces/<hash-журнала>/packet_<uuid>.json` — неизменяемые пакеты операций, включая автора и причинные зависимости.

Пакеты создаются с `overwrite=false`; изменяемого общего файла и общего манифеста нет. После загрузки содержимое проверяется повторным скачиванием. Ранее полученные неизменяемые пакеты не скачиваются заново. Локальная база и очередь операций записываются атомарно в отдельный ключ для каждого аккаунта/журнала.

**Граница доступа:** аккаунты разделяют интерфейс и локальные базы. Общий OAuth-токен даёт прямой доступ ко всем файлам этой папки приложения: пароль не создаёт серверных прав доступа, а личные журналы не зашифрованы. Эта схема рассчитана на доверенную команду. Для строгой изоляции потребуются отдельные токены либо сервер с авторизацией и/или шифрование.

История не удаляется автоматически, поэтому занимает место на Диске и в браузере. Не удаляйте отдельные пакеты вручную: они могут содержать причинные зависимости. Очистка браузера удаляет неотправленные изменения; экспортируйте JSON. Абсолютной защиты от удаления файлов владельцем токена, потери устройства или повреждения хранилища эта схема не даёт.

## Печать

На главной странице нажмите **Печать A4**.

Приложение автоматически подбирает вертикальные отступы и масштаб, чтобы журнал лучше помещался на странице A4.

## Обновление программы через Git

Если репозиторий уже клонирован на компьютер:

```powershell
cd gradebook
git pull
```

После обновления перезагрузите страницу журнала в браузере.

Данные журнала хранятся отдельно от файлов программы в браузере, поэтому обычный `git pull` не должен удалять локальную базу.

Перед крупным обновлением всё равно рекомендуется выполнить **Экспорт базы**.

gradebook/

│   ├── part-01.css

## Разработка

Для локальной разработки достаточно:

```powershell
git clone https://github.com/meshcheryakovaa/gradebook.git
cd gradebook
python -m http.server 8000
```

После изменения файлов обновите страницу браузера.

Для сохранения изменений в GitHub:

```powershell
git add .
git commit -m "Описание изменений"
git push
```

## GitHub Pages

Приложение является статическим сайтом, поэтому его можно разместить через GitHub Pages.

В репозитории откройте:

**Settings → Pages → Build and deployment → Deploy from a branch**

Выберите:

```text
Branch: main
Folder: / (root)
```

После публикации журнал можно будет открывать по веб-адресу GitHub Pages с любого устройства.

> Помните: без включённой синхронизации локальные данные `localStorage` у каждого браузера и устройства свои.

## Безопасность данных

В журнале могут находиться персональные данные студентов. Если репозиторий публичный, не добавляйте в исходный код реальные базы журналов, экспортированные JSON-файлы, OAuth-токены и другие закрытые данные.

Храните резервные копии и токены отдельно от репозитория.
