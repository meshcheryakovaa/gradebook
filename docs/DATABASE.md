# База данных Supabase (Postgres)

Журнал может хранить аккаунты и общие журналы не на Яндекс Диске, а в бесплатной базе
Postgres в [Supabase](https://supabase.com). Сервер не нужен: HTML-файл обращается к базе
прямо из браузера. Аккаунты, общие и личные журналы, работа офлайн, объединение правок и
спорные изменения работают так же, как с Диском.

Бесплатного тарифа Supabase (500 МБ, без карты) хватает на несколько преподавателей с большим
запасом: один пакет правок занимает единицы килобайт.

## 1. Создайте проект (один раз, делает один человек)

1. Зарегистрируйтесь на <https://supabase.com> (можно через GitHub) и нажмите **New project**.
2. Укажите имя, например `gradebook`, придумайте пароль базы (он понадобится только для
   прямого подключения, в журнал его вводить не нужно) и выберите регион, например
   **Central EU (Frankfurt)**. Тариф — **Free**.
3. Когда проект создастся, откройте **SQL Editor → New query**, вставьте весь файл
   [`supabase/schema.sql`](../supabase/schema.sql) и нажмите **Run**. Должно появиться
   `Success. No rows returned`.
4. Откройте **Project Settings → API Keys** (или кнопку **Connect** вверху) и скопируйте:
   - **Project URL** — вида `https://abcdefgh.supabase.co`;
   - **Publishable key** — `sb_publishable_…` (в старых проектах — `anon` `public` key).

   Секретный ключ (`sb_secret_…` / `service_role`) журналу не нужен, никуда его не вставляйте.

## 2. Подключите журнал и создайте ключ команды

1. Откройте журнал: **Настройки → База данных**.
2. Вставьте **Project URL** и **Publishable key**.
3. Нажмите **Сгенерировать ключ команды**. Под кнопкой появится строка SQL вида
   `insert into public.gradebook_keys (key_hash, note) values ('…', 'команда');` —
   выполните её в **SQL Editor** так же, как скрипт выше. В базе хранится только хеш ключа.
4. Нажмите **Сохранить и проверить**. Статус сменится на «База данных подключена».
5. Включите **Автосинхронизацию**, если она нужна.

## Вместо SQL Editor: автоматически через GitHub Actions

Скрипт и ключ команды может применять workflow `.github/workflows/db-migrate.yml`. Тогда
шаг 1.3 и строку SQL из шага 2.3 выполнять вручную не нужно.

1. В Supabase нажмите **Connect** вверху проекта и скопируйте строку **Session pooler**
   (вида `postgresql://postgres.abcdefgh:[YOUR-PASSWORD]@aws-0-eu-central-1.pooler.supabase.com:5432/postgres`),
   подставив пароль базы из шага 1.2. Строка **Direct connection** не подойдёт: она доступна
   только по IPv6, а серверы GitHub его не поддерживают.
2. В журнале нажмите **Сгенерировать ключ команды** и скопируйте ключ (кнопка **Показать ключ**).
3. В репозитории откройте **Settings → Secrets and variables → Actions → New repository secret**
   и добавьте:
   - `SUPABASE_DB_URL` — строка из п. 1;
   - `GRADEBOOK_TEAM_KEY` — ключ команды из п. 2.
4. Откройте **Actions → Database setup → Run workflow**. В журнале запуска должно быть
   `Schema applied.` и `Team key registered.`. Затем в журнале нажмите **Сохранить и проверить**.

Дальше workflow сам применяет `supabase/schema.sql` при каждом его изменении в `main`.
В базу отправляется только хеш ключа команды. Секреты не видны в журналах запусков, но
строка подключения даёт полный доступ к базе: не публикуйте её нигде, кроме секретов.
Чтобы сменить ключ, обновите секрет и запустите workflow снова; старый ключ удалите, как
описано в разделе «Безопасность».

## 3. Подключите остальных участников

Передайте коллегам лично или в мессенджере три значения: Project URL, Publishable key и
ключ команды (кнопка **Показать ключ**). Каждый вводит их на странице входа (**Хранилище →
Supabase → Параметры подключения**) вместе со своим логином и паролем и выбирает общий журнал
с одинаковым именем. Можно и как раньше: **Настройки → База данных → Сохранить и проверить**.

Без интернета войти можно на вкладке **Офлайн-вход**: пароль проверяется по аккаунту, в который
уже входили на этом устройстве, а правки отправятся в базу при первой синхронизации.

## Переход с Яндекс Диска

Ничего переносить вручную не нужно. После подключения базы каждый участник один раз нажимает
**Синхронизировать сейчас** (или ждёт автосинхронизации): его браузер отправляет в базу всю
свою историю журнала и свой аккаунт. Одинаковые правки разных участников объединяются без
повторов. Неотправленные офлайн-правки тоже уходят в базу. Аккаунт, который есть только в
кэше браузера, переносится при следующем входе с паролем.

Пока база подключена, Яндекс Диск этим браузером не используется. Кнопка **Отключить** в окне
базы возвращает обмен через Диск.

## Безопасность

- Publishable key не секретный, сам по себе он не даёт доступа к данным: таблицы закрыты,
  а каждая функция в базе проверяет ключ команды.
- **Ключ команды даёт доступ ко всем журналам в базе**, включая личные. Храните его только у
  участников и не публикуйте (в том числе в этом публичном репозитории). Ключ хранится в
  браузере и не входит в экспорт базы.
- Через приложение записи только добавляются; изменить или удалить уже записанные пакеты нельзя.
- Сменить ключ: сгенерируйте новый, выполните его строку SQL, раздайте участникам, затем
  удалите старый: `delete from public.gradebook_keys where created_at < '<дата нового ключа>';`.

## Резервные копии и паузы бесплатного проекта

- Экспорт в JSON (**Настройки → Экспорт базы**) по-прежнему работает и остаётся лучшей
  резервной копией. На бесплатном тарифе Supabase не делает загружаемые бэкапы.
- Бесплатный проект Supabase **приостанавливается после 7 дней без обращений** (например, на
  каникулах). Данные при этом сохраняются; проект возобновляется кнопкой **Restore** в панели
  Supabase. Чтобы этого не происходило, в репозитории есть workflow
  `.github/workflows/db-keepalive.yml`: добавьте секреты репозитория `SUPABASE_URL` и
  `SUPABASE_PUBLISHABLE_KEY` (**Settings → Secrets and variables → Actions**), и он будет
  обращаться к базе раз в три дня. Ключ команды для этого не нужен, данные не читаются.

## Если не подключается

- «В базе нет функций журнала» — скрипт `supabase/schema.sql` не выполнен или выполнен в
  другом проекте. Выполните его ещё раз (повторный запуск безопасен).
- «Неверный ключ команды» — не выполнена строка `insert into public.gradebook_keys …` или
  ключ скопирован не полностью.
- «Неверный publishable (anon) key» — проверьте ключ в **Project Settings → API Keys**.
- «Нет связи с базой данных» — проверьте адрес проекта и интернет; если проект приостановлен,
  возобновите его в панели Supabase. Если HTML открыт двойным щелчком и браузер блокирует
  запросы, откройте его через `http://localhost:8000/` (см. README).

## Web-версия на GitHub Pages

Workflow `.github/workflows/pages.yml` публикует журнал как сайт и подставляет настройки
хранилища из секретов репозитория. Тогда на странице входа не нужно вводить адрес проекта и
publishable key, а если заданы необязательные секреты, то и ключ команды и токен Диска.

1. **Settings → Pages → Build and deployment → Source: GitHub Actions** (один раз).
2. Секреты (**Settings → Secrets and variables → Actions**):
   - `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY` — те же, что для keep-alive. Они не секретные
     по своей природе, встраивать их безопасно.
   - `WEB_TEAM_KEY` и `WEB_YANDEX_DISK_TOKEN` — **необязательно**. Всё, что попадает на сайт,
     может прочитать любой, кто его открыл: с ключом команды это доступ ко всем журналам в базе,
     с токеном — ко всем файлам журнала на Диске. Задавайте их, только если адрес сайта знает
     лишь ваша команда. Без них каждый вводит ключ команды (или токен) один раз на устройстве.
     Секреты `GRADEBOOK_TEAM_KEY` и `YANDEX_DISK_TOKEN` на сайт не попадают.
3. **Actions → Web version (GitHub Pages) → Run workflow** или любой мерж в `main`, меняющий
   код журнала. Адрес сайта появится в журнале запуска и в **Settings → Pages**.

Настройки, введённые на устройстве (в окне **База данных** или на странице входа), всегда
важнее встроенных. Файл релиза (`Gradebook-vX.html`) настроек не содержит.
